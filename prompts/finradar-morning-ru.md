1) Сначала ПРИВЕДИ единицы спота и фьючерса к одной шкале (scale). Типичные ISS-случаи:
   - RGBI спот ↔ RB* / RGBIF: если settle фьючерса ≈ спот×100 → спот_экв = CLOSE_fut / 100
   - USD TOM ↔ Si*: обычно Si/1000 = USD/RUB
   - IMOEX ↔ MX*: обычно MX/100 = пункты индекса
   - Акции ↔ срочные: проверь LOTVOLUME / шаг цены; если вечный *F совпадает 1:1 — scale=1

     GD_в_₽/г = CLOSE(GD*) × CLOSE(USD000UTSTOM) / 31,1034768
     базис_₽/г = GD_в_₽/г − CLOSE(RUGOLD)
     базис_%   = (GD_в_₽/г / RUGOLD − 1) × 100
     Серебро — то же с SV* и RUSILVER.
2) После выравнивания:
   базис = фьючерс_в_единицах_спота − спот
   базис_% = (фьючерс_в_ед_спота / спот − 1) × 100
3) Ярлык режима срочности (по знаку базиса после выравнивания):
   - базис > 0 → КОНТАНГО (срочный дороже спота / ближний дороже дальнего — уточни тип пары)
   - базис < 0 → БЭКВОРДАЦИЯ (срочный дешевле спота)
   - |базис_%| мал относительно своих 5/20 сессий → НЕЙТРАЛЬНО / сжато
4) Для календаря near↔far (два фьючерса одного актива):
   календарный_базис = far − near (в одной шкале)
   far > near → календарное контанго; far < near → календарная бэквордация.
5) Всегда пиши: код контракта(ов), TRADEDATE, scale, базис в пунктах/%, базис вчера, знак режима.
   Запрещено писать «базис н/д» / «контанго н/д», если обе ноги CLOSE есть — сначала выровняй scale.

ОБЯЗАТЕЛЬНО называть КОНКРЕТНЫЕ КОДЫ ISS (SECID), не общие слова «фьючерс/спот»:
- Фьючерс: RBZ6, SiZ6, CRZ6, GDZ6, SVZ6, MXZ6, SRZ6, GZZ6, MEZ6, VBZ6, RGBIF …
- Спот/индекс/валюта: RGBI, USD000UTSTOM, CNYRUB_TOM, RUGOLD, RUSILVER, IMOEX, SBER, GAZP …
- Календарь: оба кода, напр. RBZ6 и RBH7.
Без кода ноги строку в B7 не ставь — сначала найди SECID на ISS.

Для КАЖДОЙ строки из карты B6 (и отдельно для календаря near/far, если посчитан):
1) Факт: актив, ноги (SECID), scale, базис, базис_%, режим, базис вчера, сдвиг базиса за 1/5 сессий.
2) Каркас пары (механически по знаку):
   - КОНТАНГО (срочный богаче спота / far богаче near):
     идея сжатия базиса → ШОРТ дорогой ноги (фьючерс / far) + ЛОНГ дешёвой ноги (спот / near)
     классика: cash-and-carry / short calendar
   - БЭКВОРДАЦИЯ (срочный дешевле спота / far дешевле near):
     идея расширения к справедливой / схождения вверх → ЛОНГ дешёвой срочной ноги + ШОРТ дорогой спотовой / near
     классика: reverse cash-and-carry / long calendar
   - НЕЙТРАЛЬНО: «пары нет — базис внутри своего окна; не раздувать»
3) Формат строки-подсказки (жёсткий шаблон — две колонки с кодами + отдельная строка-приказ ног):
   | Актив | Режим | ЛОНГ (SECID) | ШОРТ (SECID) | Зачем | Риск срыва |
   Сразу под таблицей или в колонках — дословно:
   `ЛОНГ: <SECID>  |  ШОРТ: <SECID>`
   Примеры правильных строк:
   - `ЛОНГ: USD000UTSTOM  |  ШОРТ: SiZ6`
   - `ЛОНГ: RUGOLD  |  ШОРТ: GDZ6`
   - `ЛОНГ: RBZ6  |  ШОРТ: RBH7`   (календарь, если far в контанго)
   - `ЛОНГ: SVZ6  |  ШОРТ: RUSILVER`  (бэквордация)
   Запрещены формулировки без кода: «лонг спот / шорт фьюч», «купить ближний».
4) Не предлагай голый односторонний вход («только шорт RBZ6»). Только две ноги одного актива — оба SECID.
5) Не смешивай разные активы в одну «пару» (нельзя SiZ6 vs GDZ6 как базисная пара).
6) Если спот-нога недоступна на счёте (нельзя шортить RGBI/IMOEX) — явно:
   `спот-нога недоступна → календарь` и строка `ЛОНГ: <near SECID>  |  ШОРТ: <far SECID>` (или наоборот по знаку).
7) Без слов «гарантированный заработок». Пиши: «ставка на сжатие/расширение базиса», ГО, комиссии, FX для металлов, экспирация.
8) В конце B7 — блок «Итого ноги дня» (обязателен):
   Топ-3 пары, каждая одной строкой:
   `N) <актив> · <режим> · ЛОНГ: <SECID> · ШОРТ: <SECID> · базис …`
   Сортировка по |сдвигу базиса| или |базис_%|; только где оба SECID ликвидны; без market-view.
